# AppDeck

Каталог установленных программ для Windows: сканер реестра, запуск, удаление
и карточки приложений.

[Скриншот AppDeck](docs/screenshots/appdeck-main.png)

## Что это

AppDeck сканирует реестр Windows и системные пути, находит установленные
программы и собирает их в единую библиотеку с поиском, фильтрами и карточками.
Для каждого приложения доступны запуск, открытие папки установки и удаление.

## Возможности

- сканирование установленных программ из реестра и меню «Пуск»;
- каталог с поиском и сортировкой;
- карточка приложения: имя, версия, издатель, путь установки;
- запуск программы и открытие её папки прямо из карточки;
- удаление приложения через системный деинсталлятор;
- тёмная тема интерфейса.

## Запуск проекта

Требуется Node.js 18+.

```bash
npm install
npm run dev      # запуск в режиме разработки
npm run build    # сборка установщика
# AppDeck — инструкция для сборщика

Лаунчер-библиотека установленных программ Windows. Один и тот же интерфейс работает в браузере (прототип) и в Electron (нативная версия). Все нативные возможности находятся в `electron/` и **активируются только внутри Electron**.

## Команды

```bash
npm install            # зависимости
npm run dev            # браузерный прототип с hot reload (http://localhost:5173)
npm run build          # production-сборка в dist/index.html
npm run preview        # проверка собранного dist/ в браузере
node scripts/native-check.cjs   # проверка Electron-модулей и каталога (без запуска Electron)
```

Запуск Electron в разработке:

```bash
npm run electron:dev     # одна команда: поднимает Vite на :5173 и открывает окно Electron
```

`electron:dev` сам ждёт готовности dev-сервера (опрос `http://localhost:5173` каждые 300 мс, таймаут 60 с),
поэтому `concurrently` и `wait-on` не нужны — зависимостей меньше. Если Vite уже запущен, скрипт его переиспользует.
Дополнительные флаги Electron передаются после `--`, например
`npm run electron:dev -- --remote-debugging-port=9222`. При закрытии окна оба процесса завершаются.

Раздельный запуск (два терминала):

```bash
npm run dev              # терминал 1, Vite
npm run electron:start   # терминал 2, только окно против уже запущенного сервера
```

`electron:start` читает `VITE_DEV_SERVER_URL` (по умолчанию `http://localhost:5173`) и падает с понятной
ошибкой, если сервер не отвечает. `electron-builder` в проекте нет: сборка дистрибутива — отдельная задача.

Сборка установщика: `npm run build`, затем `npx electron-builder --win --x64` (конфигурация `build` добавляется в `package.json` сборщиком; см. раздел «Что нужно сделать в сборке»).

## Что работает в браузерном прототипе

- 147 программ из `programs.ts`, поиск по имени/издателю/описанию, фильтры по 9 категориям (счётчики совпадают с карточками), сортировка по названию, категории и дате.
- Пять тем (тёмная, светлая, AMOLED, тёплая, Nord): переключение без перезагрузки, выбор хранится в `localStorage` (`appdeck.theme`). Nord построена на официальной палитре nordtheme.com; см. комментарий в `style.css`.
- «⋯» на каждой карточке: Подробнее, Открыть папку, Найти в интернете, GitHub (если есть проверенный репозиторий), Найти аналоги, Удалить.
- Удаление: диалог подтверждения → карточка помечается «Удалено» → после «Обновить» исчезает. **Реально ничего не удаляется.**
- Open Source: бейдж и кнопка GitHub только для программ с `isOpensource: true` и валидным `repoUrl`.
- Аналоги: 2–4 проверенных варианта из `descriptions.json`; наличие в библиотеке проверяется по списку.
- Описания: только из `descriptions.json`. Неизвестные программы получают «Описание не найдено»; ничего не выдумывается.

## Что активируется только в Electron

1. **Реестр Windows.** `reg query` по трём веткам Uninstall (HKLM, WOW6432Node, HKCU). Фильтры: `SystemComponent=1`, обновления и дочерние записи пропускаются, дубликаты по имени+версии убираются. Кодировка вывода: UTF-8, затем cp866 (OEM).
2. **Категории.** `electron/catalog.cjs` сопоставляет имя из реестра с `descriptions.json`: точное совпадение после нормализации или самое длинное имя-префикс, после которого идёт только версия/редакция (`7-Zip 26.04 (x64 edition)` → `7-Zip`). «Google Chrome» не получает категорию Google.
3. **Иконки.** `electron/icons.cjs` берёт `DisplayIcon`, извлекает иконку через PowerShell и сохраняет PNG в `%USERPROFILE%\.app-library\icons\<id>.png`. Повторные сканирования используют кэш. Без иконки остаётся буква.
4. **Удаление.** Подтверждение одно — диалог в интерфейсе с текстом «Удалить [название]? Это действие нельзя отменить. Запустится uninstaller программы». `app:uninstall` вызывается только из обработчика кнопки «Удалить» этого диалога; нативного диалога нет. Главный процесс заново читает `UninstallString` из реестра. MSI-продукты удаляются командой `msiexec.exe /x {ProductCode} /passive`, остальные — через `spawn` с разобранными аргументами. `shell.open` для удаления не используется. `.cmd`/`.bat` не запускаются.
5. **Безопасность IPC.** Каждый обработчик проверяет отправителя (`assertTrustedSender`). Пути запуска и папки берутся из последнего скана, а не из произвольной строки от renderer. Внешние ссылки открываются только из allowlist каталога.
6. **Окно.** `titleBarOverlay` на Windows; класс `is-electron` резервирует место под системные кнопки в шапке.
7. **Автоскан при старте.** В Electron реестр сканируется сразу после открытия окна, без нажатия «Обновить». Пока идёт скан, виден статический список.
8. **Свои описания и скриншоты.** Карандаш рядом с «Описание» открывает редактор (до 4000 символов; пустое поле сбрасывает правку). «Добавить скриншот» открывает системный диалог (PNG, JPG, WebP, до 25 МБ) и **копирует** файл в папку приложения, поэтому исходник можно удалять.
   - Хранилище: `overrides.json` в `app.getPath("userData")` (Windows: `%APPDATA%\<имя приложения>\`), структура `{ [ключ]: { description?, screenshot? } }`. В `screenshot` лежит имя файла из `userData/screenshots/`.
   - **Ключ записи — ключ реестра** (`HKEY_…\Uninstall\7-Zip`, в нижнем регистре), а не название. Название меняется при обновлении («7-Zip 26.04» → «26.05»), ключ реестра обычно нет, поэтому описание и скриншот остаются на карточке. Если у программы пустой ключ реестра, запись хранится под именем-идентификатором (`7-zip-26-04-x64-edition`); при смене названия такая запись отвяжется. Логика в `electron/overrideKeys.cjs`.
   - **Миграция.** Старые записи с ключом-названием при скане переносятся на ключ реестра (сопоставление по названию), старые записи удаляются, файл сохраняется один раз. Записи программ, которых нет в реестре, остаются как есть, повторный скан ничего не меняет. Если у программы нет ключа реестра, запись остаётся под именем. Если прежнее название уже изменилось до обновления приложения, такую запись перенести нельзя: сопоставлять не с чем.
   - Имя файла скриншота — `<programId><ext>`; если оно уже принадлежит другой записи (программу переименовали, а её старое имя заняла другая), к имени добавляется короткий хеш ключа, чужая картинка не перезаписывается.
   - **Ограничение:** MSI-программы называют ключ реестра по ProductCode (GUID), и при мажорном обновлении он может смениться. Тогда привязка теряется так же, как раньше при смене названия. У большинства exe-установщиков (Inno Setup, NSIS, 7-Zip, Chrome) ключ стабилен.
   - Запись атомарная (временный файл + переименование). Битый JSON не роняет приложение: файл переименовывается в `overrides.json.corrupt-<время>`.
   - Правки накладываются при каждом скане, поэтому переживают «Обновить», перезапуск и переустановку `node_modules`.
   - Картинки отдаются через свой протокол `appdeck-media://screenshots/<файл>`: в dev-режиме страница открыта с `http://localhost`, и Chromium блокирует `file://`. `webSecurity` не отключается. Протокол отдаёт только файлы из `userData/screenshots`.
   - В браузерном прототипе правка описания живёт до перезагрузки страницы, скриншоты недоступны.
9. **Автообновление после удаления.** После запуска uninstaller главный процесс раз в 2 секунды проверяет реестр (до 90 секунд). Когда программа исчезла, он пересканирует и шлёт окну событие `registry:updated`. Если uninstaller работает дольше 90 секунд, остаётся ручное «Обновить».

### Если `npm run electron:dev` не запускается на Windows

- `spawn EINVAL` после «Запускаю Vite…»: Node ≥ 22.12 не запускает `.cmd` напрямую. В `scripts/electron-dev.mjs` `npx` теперь вызывается через оболочку (`shell: true` только на Windows).
- `Electron failed to install correctly`: проблема локальной установки пакета. Проверьте `Test-Path node_modules\electron\dist\electron.exe`. Если `False` — очистите `%LOCALAPPDATA%\electron\Cache` и выполните `node node_modules\electron\install.js` (переменная `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` ускоряет загрузку). Если zip скачан, но не распакован: `Expand-Archive` из `electron-v<версия>-win32-x64.zip` в `node_modules\electron\dist` и файл `node_modules\electron\path.txt` со строкой `electron.exe`.

## Структура

```
electron/
  main.cjs        окно, IPC, скан → категории → иконки → правки пользователя, overrides.json, протокол appdeck-media

  overrideKeys.cjs  ключ правок пользователя (ключ реестра, запасной — имя), миграция старых записей, имена файлов скриншотов

  icons.cjs       извлечение и кэш иконок
src/
  App.tsx         состояние библиотеки, поиск, фильтры, удаление, маппинг скана
  components/     карточки, меню, модалки, ProgramIcon, ThemePicker, Electron-гайд
  data/           programs.ts, descriptions.json, alternativeDetails.json, themes.ts, catalog.ts
  styles/style.css  CSS-переменные всех тем и адаптивность
  utils/          catalog.ts (метаданные, сортировка, формат размера), cn.ts
scripts/native-check.cjs  проверки парсеров, сопоставления и инвариантов данных
```

## Данные: правила

- `descriptions.json` — 151 запись (147 из списка + Trilium Notes, OxidVault, SpaceWalk, TiXL-RU). Четыре последние добавлены только в каталог: в прототип они не попадают, потому что список 147 — это скан вашего ПК. Они начнут отображаться, если скан их найдёт.
- Поля записи: `description`, `category`, `isOpensource`, `repoUrl`, `alternatives`.
- `description: null` и `repoUrl: null` — правило «не уверен, значит null». Выдуманная ссылка хуже отсутствующей.
- `isOpensource: true` только с подтверждённым репозиторием. Craft App Suite и Everything — `false` (Everything — freeware с закрытым кодом).
- Аналоги: 2–4 записи, без самоссылок, без версий одного SDK. Для «Прочее» список пуст.
- `scripts/native-check.cjs` проверяет эти правила и совпадение категорий со статическим списком.

## Что нужно сделать в сборке (перед выпуском)

1. **Включить каталог в упаковку.** `electron/catalog.cjs` читает `src/data/descriptions.json`. Electron-builder по умолчанию не кладёт `src/` в asar, поэтому главный процесс упадёт при старте. Добавьте в конфигурацию сборщика файл `src/data/descriptions.json` в `files` (или скопируйте в `electron/data/` при сборке).
2. **Настроить `package.json`.** Поля `main: "electron/main.cjs"`, `build.appId`, `build.win.target: "nsis"`. Файл вносится вручную или через `npm pkg set`; в этом проекте package.json не редактируется напрямую.
3. **Подписать установщик.** Без подписи Windows SmartScreen предупредит пользователя.
4. **Проверить на Windows.** Части, которые нельзя проверить на Linux: `reg query` с кодировкой, `ExtractAssociatedIcon`, `msiexec /x`, `spawn` uninstaller, `shell.openPath`. Проверьте на тестовой программе, которую можно безопасно удалить.
5. **Время первого сканирования.** Извлечение иконок занимает до нескольких десятков секунд при 147 программах (пул из 4 процессов). Последующие сканы берут PNG из кэша.

## Известные ограничения и TODO

- `findAlternatives` доступен в preload и main, но renderer использует статический каталог. Подключите вызов в `AlternativesModal` при переходе на API или локальную базу соответствий.
- Удаление подтверждается один раз, в интерфейсе. Главный процесс доверяет вызову `app:uninstall` от собственного окна (`assertTrustedSender`); защита от случайного удаления держится на диалоге renderer.
- `EstimatedSize` есть не у всех программ; тогда показывается «нет данных».
- Иконка берётся из `DisplayIcon`. Если там `.dll` или `.ico`, иконка не извлекается и остаётся буква.
- `TODO: заменить статические описания на реальный поиск через API` — в `descriptions.json`.
- Контраст подписей всех 9 категорий с фоном карточек (минимум): тёмная 5.82, светлая 5.08, AMOLED 7.05, тёплая 7.05, Nord 5.61. Все ≥ 4.5 (WCAG AA); светлая тема ниже 5.5. Пользовательского выбора акцента в приложении нет: акценты фиксированы в темах.
- Nord: 5 цветов категорий и цвет текста «Удалить» — официальный оттенок, смешанный с nord6 (см. комментарий в `style.css`), потому что чистые nord9/10/11/12/15 дают 3.05–4.64 даже на nord0. Акцент nord8 на всплывающих панелях nord1 — 5.03 (там он используется только для иконок).
